# Agent Note: Desktop 0.4 运行时与 Windows 集成

Status: proposed

[English](2026-08-26-desktop-0.4-runtime-and-windows-integration.md) | 中文

## Problem

桌面壳拥有顶层 Node 运行时，但只保留并终止其直接 `Child`。模型工具启动的进程由 `ctx.subprocess` 管理，桌面壳直接启动的宿主 Node 不在该服务内；运行时异常退出或应用关闭时，其后代 Node 进程可能遗留。标题栏余额接口始终查询 DeepSeek 官方账户，即使当前会话已选择其他提供方，账户状态也不会同步变化。桌面生产模式禁用了浏览器右键菜单，却没有补回基本文本操作。Windows 组合即使检测到可用的 WSL 2，也只向 AI 提供 PowerShell。

## Proposal

Desktop 0.4 将需求拆成四个可独立审查的切片，并在最后进行一次版本集成。P1 建立桌面运行时整棵进程树的原生所有权；P2 让账户标题栏跟随当前会话提供方；P3 提供仅桌面端启用、可访问的右键菜单；P4 在 Windows 上增加用户主动启用的 WSL 2 Bash 执行环境。若实现过程中出现新的长期架构决策，每个切片须更新本文或另建更窄的 Agent Note。

本版本不修改 `agent-loop`、会话日志格式或既有 shell 工具的模型可见语义。切换模型与右键操作不会产生模型可见输入。启用 WSL 会改变下一次请求的工具目录，必须由现有系统提示组装与请求头记录机制体现，不新增会话事件类型。

## P1：管理桌面运行时进程树

Tauri 壳继续作为运行 `dsh web` 的 Node 进程的外部监督者；`ctx.subprocess` 位于该 Node 进程内部，不能反过来拥有自己的宿主。将 `DshRuntime(Mutex<Option<Child>>)` 改为运行时监督器，状态包含根进程身份、平台隔离句柄、生命周期状态，以及唯一的幂等 `terminate_and_join(reason, budget)` 操作。

Windows 启动流程先以挂起状态创建运行时，将其加入启用 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 的私有 Job Object，再恢复执行。Job 创建或分配失败时不得静默退化为只管理直接子进程；启动页必须显示错误并停止启动，因为进程隔离是桌面启动保证。正常退出先请求运行时优雅关闭，在限定时间内等待，随后终止 Job 并等待根句柄；桌面壳销毁时关闭 Job，作为最终同步兜底。Job Object 通过所有权覆盖运行时从 `node_modules` 启动的 Node worker 与其他后代，不按进程名扫描，也不影响无关 Node 安装。

POSIX 平台将运行时放入独立进程组，先向组发送 TERM，在可配置的限定宽限期后发送 KILL，并等待根进程结束。监督器容纳 ESRCH 与退出竞态，但将超时和隔离失败写入桌面日志。`quit_app`、`RunEvent::ExitRequested`、启动超时、就绪通道断开、重试、更新器重启和致命启动错误全部调用同一个操作；其他路径不得直接调用 `Child::kill`。关闭到托盘继续保持运行时存活。

实现先在 `apps/desktop/src-tauri/src/` 中建立纯生命周期状态机与平台适配器，`main.rs` 只保留编排。增加目标平台原生夹具：启动根 Node、Node 子进程和脱离的孙进程，输出各自身份后等待。测试覆盖优雅退出、升级终止、重复终止、清理前根进程已退出、分配隔离资源后启动失败和应用退出清理。打包 smoke 必须确认私有 Job／进程组中不再有成员；禁止按进程名进行全局清理。

## P2：让余额标题栏跟随所选提供方

标题栏需要提供方感知的账户状态，而不是 DeepSeek 专用轮询。桌面桥接新增类型化账户摘要接口，请求携带当前会话 id 与所选提供方 id。Host 解析权威的当前 `ModelSelection`，不得信任浏览器提交的端点或凭据引用。提供方可注册 effect-scoped 账户摘要能力，返回 `available`、`unsupported`、`unconfigured` 或 `unavailable`，并可附带金额与币种。DeepSeek 适配器拥有现有 `/user/balance` 实现；没有账户接口的提供方返回 `unsupported`，标题栏隐藏金额并显示当前提供方，不得保留旧余额。

桌面客户端订阅 client runtime 已拥有的当前会话 `modelSelection` 快照。打开会话、重连或 `session.selectModel` 成功后，立即作废旧请求、清除其他提供方的金额，并查询新提供方。响应必须携带或核对 `{sessionId, providerId, generation}`，旧请求不得覆盖新选择。保留五分钟轮询和窗口重新可见时刷新，但每次轮询都重新解析选择。凭据与设置更新通过既有转发事件触发刷新。

不得新增标题栏专用的提供方变化事件，也不得从 DOM 标签推断提供方。把账户控制器从注入的无类型脚本迁入 `bridge-client`，`titlebar.js` 只保留稳定挂载点。聚焦测试覆盖 DeepSeek 成功、提供方不支持、凭据替换、会话切换、乱序响应、成功后刷新失败、语言变化和资源释放。显示规则是硬约束：选择提供方 B 时绝不显示来自提供方 A 的金额。

## P3：桌面右键菜单

`bridge-client` 用桌面自有的 body portal 替换生产模式的右键完全禁用。对不可编辑区域内选中的文本，菜单提供“复制”；在当前会话 composer 上提供“剪切”“复制”“粘贴”，并根据选区、禁用／只读状态和剪贴板能力决定是否可用。会话 composer 之外的输入控件只允许复制，避免设置、密码和确认输入框获得意外修改路径。

写入剪贴板复用共享 clipboard primitive。修改 composer 使用 `setRangeText` 或原生 textarea value setter，并触发冒泡 `input` 事件，使 React 与 session input machine 继续保持权威。粘贴只读取纯文本，替换当前选区，在 WebView 支持范围内保留撤销与焦点，不接收文件或 HTML。执行动作、Escape、外部指针、滚动、窗口缩放、失焦、会话导航或插件释放都会关闭菜单；使用 roving focus 支持上、下、Home、End、Enter 与 Space。菜单位置限制在 visual viewport 内，并在靠近右侧或底部时翻转。

调试模式可在产品操作之后显式增加“检查”，但不恢复不可控的浏览器菜单。测试覆盖目标与选区分类、仅 composer 可修改、剪贴板权限拒绝、空选区、禁用控件、输入法安全、边缘定位、键盘导航、语言切换和 effect 清理。该功能改变用户可见 GUI，必须从真实桌面 evidence server 录制浏览器证据和 GIF。

## P4：Windows 上主动启用 WSL 2 Bash

在 Desktop 设置中增加仅 Windows 显示的环境卡片。检测通过有时间上限的原生命令执行，返回类型化快照：`not-installed`、`no-distribution`、`wsl1-only`、`ready` 或 `error`，并包含可用的 WSL 2 发行版与当前默认项。用 `wsl.exe --status` 和 `wsl.exe --list --verbose`，将解析器隔离在本地化及旧版本输出夹具后；启用前必须在所选发行版内执行探针，不能只相信列表。UI 提供“通过 WSL 2 启用 Bash”、必要时选择发行版、刷新、停用，以及无法原子热切换时的“需要重启”状态。

设置只在既有 desktop settings namespace 中保存 `{enabled, distribution}`。软件不得自动安装 WSL、转换发行版版本、修改 Windows 默认发行版或下载发行版。环境缺失时，只有用户主动点击后才通过原生 opener 打开微软安装说明。

新增 Windows 专用 WSL subprocess provider，不让 `bash-local` 按宿主平台分支。该 provider 使用固定的 `wsl.exe --distribution <name> --exec ...` argv，将权威 Windows Workspace cwd 通过 `wslpath` 转换，沿用 subprocess 凭据清理规则，并拥有 Windows 侧 `wsl.exe` 进程树的终止。配套 Bash executor 在该执行环境解析命令；仅当设置启用且探针健康时注册既有 `bash` Consumer。普通 `pwsh` 工具始终保留。重复注册 `bash`、所选发行版缺失、路径转换失败或发行版失联都必须明确失败，并从后续工具组装中移除 Bash。

P4 实现前必须证明文件系统与 sandbox 语义。最终方案必须为同一执行环境提供 WSL filesystem provider，或者明确把 Bash 的 cwd 与文件引用限制为 `/mnt` 下转换得到的 Windows 路径，并在 executor 层强制执行当前 permission preset。只用 `wsl.exe bash -c` 包装命令、却允许不受限制的 Linux 路径不可接受，因为这会让 `ctx.fs` 与 `ctx.shell` 对执行环境产生分歧，并绕过 Windows sandbox 立场。首个版本不支持 WSL 1、非默认 interop 挂载、远程 WSL 主机、自动安装软件包或持久 WSL terminal。

单元测试覆盖检测解析、探针失败、设置状态转换、路径转换、不经 shell 拼接的 argv、工具注册释放、PowerShell 与 Bash 同时存在的目录以及权限拒绝。Windows 目标平台集成测试在可用时通过真实 WSL 2 发行版执行 `bash`；不可用时须给出明确自跳过原因，但不能算作 Windows 证据。无密钥 assembled snapshot 验证启用 Bash 会改变已记录工具目录，停用后工具被移除。

## Delivery sequence

1. **P0——基线与接口：** 用夹具复现遗留进程，捕获余额竞态，清点右键目标，并记录 WSL 命令输出夹具；先冻结类型接口与失败状态，再开发 UI。
2. **P1——运行时监督器：** 落地原生进程隔离，并让所有退出路径汇入同一清理操作。后续开发依赖确定性清理，因此这是版本阻断项。
3. **P2——账户摘要：** 增加提供方能力，把 DeepSeek 余额归还其所有者，让桌面控制器订阅会话模型选择，并删除旧的无条件余额接口。
4. **P3——右键菜单：** 增加 portal、剪贴板／编辑适配器、语言文本、客户端测试、浏览器证据，以及来自真实桌面 evidence server 的必要 GIF。
5. **P4a——WSL 发现 UI：** 先落地只读检测与明确设置状态，不向 AI 暴露 Bash。
6. **P4b——WSL 执行：** 落地经批准的文件系统／sandbox 方案、provider、条件工具组合、assembled snapshot 和 Windows 原生证据。
7. **版本集成：** 更新 desktop README 中英文对、Changelog、设置文档、受影响包的 README／JSDoc 和本文；把桌面唯一版本源升为 `0.4.0`，执行版本同步并运行目标平台 release smoke。*(状态:应实现请求提前落地 0.4.0 版本;README/中文对已为 P1 更新。)*

除非实现与证据无法独立成立，每个阶段使用一个可审查 PR。P1 接口稳定后，互不依赖的 P2 与 P3 可并行。P4b 在权限与文件系统决定通过审查前不得合并。

## P4b 设计决定(文件系统与 sandbox 语义)

P4b 实现 Windows 专属 WSL subprocess provider,外加匹配的 Bash executor 与 tool,但不教 `bash-local` 按宿主 OS 分支。由于 `ctx.shell` 是单 executor seam(Windows 挂 pwsh-sandbox;POSIX 挂 bash-sandbox),WSL Bash 不能替换 `ctx.shell` 而不丢掉 PowerShell —— 因此 WSL 执行世界以自有的 provider/executor/tool 三元组(`subprocess-wsl`、`bash-wsl`、`tool-bash-wsl`)交付,仅在 WSL 设置启用且探针健康时注册;普通 `pwsh` tool 保持挂载。executor 以固定 `wsl.exe --distribution <name> --exec ...` argv 启动,经 `wslpath` 翻译权威 Windows Workspace cwd,按 subprocess 规则清洗凭据,并拥有 Windows `wsl.exe` 树的终止。

文件系统/sandbox:本版本采用显式限制选项 —— WSL Bash 的 cwd 与文件引用是经 `/mnt` 翻译的 Windows 路径(仅默认 interop 挂载;WSL 1、非默认 interop 挂载、远程 WSL 主机、自动安装包与持久 WSL 终端不在范围内)。executor 在请求边界强制每个路径参数都解析到翻译后的 workspace root 之下,匹配活跃 permission preset 的 `workspaceRoot` 与 sandbox mode;越出翻译根目录的路径可见地失败,并从后续工具组装中移除 Bash。这使 `ctx.fs` 与 `ctx.shell` 保持一致,而不必交付完整 WSL filesystem provider。重复 `bash` 注册、缺失所选发行版、路径翻译失败或发行版丢失均可见地失败。一个无 key 的 assembled snapshot 验证启用 Bash 改变记录的工具目录,禁用则移除该 tool。

智能体先添加能够证明验收路径的失败聚焦测试或夹具，再完成最小的插件归属修改，同步更新中英文所有者文档，并通过 `dsh-pre-push-checks` 选择窄检查。不得修改 `agent-loop`，不得为预发布行为添加兼容垫片，不得硬编码随部署变化的超时，不得按可执行文件名匹配任意进程，不得向浏览器暴露凭据，也不得把自跳过的 WSL 测试当作 Windows 证据。

每次交接须报告修改文件、实际运行命令、剩余风险和下一阶段前置条件。只有成功路径与清理／释放路径得到同等强度测试后，该阶段才算完成。

## Alternatives considered

**让 `ctx.subprocess` 管理桌面运行时。** 不采用，因为该服务位于需要被终止的 Node 运行时内部，不能提供外部崩溃兜底。

**终止当前用户的所有 `node.exe`。** 不采用，因为可执行文件名不证明所有权，可能终止无关开发工具；私有 Job Object 或进程组才携带精确所有权。

**新提供方返回金额前继续显示 DeepSeek 余额。** 不采用，因为过期财务信息比明确的“不支持”状态更有误导性。

**恢复 WebView 原生右键菜单。** 不采用，因为它依赖平台，包含不需要的浏览器／开发操作，也无法一致限制只有 composer 能修改。

**只要存在 `wsl.exe` 就向 AI 暴露 Bash。** 不采用，因为 WSL 1、无发行版、启动损坏或文件系统／sandbox 语义不兼容都不构成安全可用的执行环境。

**用 WSL Bash 替换 PowerShell。** 不采用，因为 WSL 是可选环境，两种工具对应不同 Windows 工作流；启用 Bash 是增加能力，不删除 PowerShell。

## Acceptance criteria

- 所有受支持桌面平台在正常退出、启动失败、重试和更新器重启时都终止运行时拥有的完整进程树；目标平台原生夹具不留下任何成员，无关 Node 进程保持存活。
- 标题栏账户状态立即跟随活动会话的提供方，绝不渲染为旧会话或旧提供方取得的金额。
- 桌面生产模式右键对已选可读文本提供复制，仅在会话 composer 中提供剪切／复制／粘贴，并支持键盘与屏幕阅读器操作。
- Windows 检测 WSL 2 时不修改机器；只有用户明确确认且探针成功后才启用 Bash，同时保留 PowerShell，并在停用或环境失效时移除 Bash。
- WSL Bash 与文件操作使用相同活动 Workspace 和权限立场，不发布无限制命令包装器。
- 用户可见变更具有聚焦客户端测试；工具目录变化有无密钥 assembled coverage；生命周期与 WSL 有目标平台原生证据；中英文文档已更新；右键功能包含 GIF。
- 发布前通过 `pnpm run doc-sync`、相关聚焦 Vitest／Cargo 测试、`git diff --check`、桌面版本检查和受影响目标平台 packaged smoke。

## Risks

Windows Job Object 分配可能与外层 Job 冲突，必须在打包 runner 上验证创建标志和 breakaway 行为。优雅关闭可能暴露既有资源释放延迟，因此预算超时必须产生诊断，不能静默强杀。各提供方账户接口不同，部分提供方会明确保持不支持。剪贴板读取可能需要 WebView 权限和用户激活。WSL 输出本地化与路径映射是不稳定输入；如果 P4b 没有执行型约束，WSL Linux 文件系统可能逃逸仅面向 Windows Workspace 的策略。这些风险要求四个切片可以独立回退，并把 P1 和 P4 权限决定作为版本门槛。
