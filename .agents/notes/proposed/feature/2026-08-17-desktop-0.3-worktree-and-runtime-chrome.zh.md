# Agent Note: 桌面端 0.3 Worktree 与运行状态栏

Status: proposed

[English](2026-08-17-desktop-0.3-worktree-and-runtime-chrome.md) | 中文

## 问题

桌面客户端以 Workspace 和 Session 为导航中心，但没有用于检查文件、搜索源码或查看 Git 变更的工程视图。用户必须离开应用才能完成这些常见的定位工作。标题栏显示余额，却不显示 API 可达性或本地运行时负载，余额也不能直接刷新；启动界面使用与打包应用图标无关的色块。共享消息状态栏已支持普通消息复制，但其位置与覆盖范围尚不能保证每条普通用户消息和助手消息旁边都有复制操作。

## 提案

桌面端 0.3 在现有 Workspace 模式旁增加 Worktree 模式，补齐普通消息复制入口，并在原生标题栏中增加紧凑的运行状态区。本提案中的“Worktree”是以所选 Workspace 目录为根的工程视图；它不创建、删除或切换 Git `worktree` checkout。

该版本仍拆成可独立审查的改动。每项用户可见的实现都会更新本提案；如果形成更窄且持久的架构决策，则另建 Agent Note。开发未完成时，`0.3.0` Changelog 章节保持为空；草稿 Release 发布前只写入已经交付的行为。

## Worktree 模式

现有 `sidebar.workspaces` slot 改为工作台所有者的挂载点。该所有者渲染持久且无障碍的 Workspace/Worktree 模式切换控件，并为两个模式各声明一个子 slot。当前 Workspace 浏览器不改变行为，迁入 Workspace 子 slot。新的 Worktree UI 插件占用 Worktree 子 slot，并拥有包含资源管理器、搜索和源代码管理视图的活动切换控件。所选模式与活动是浏览器本地的展示偏好；切换它们不会改变选中的 Workspace 或 Session。

所有 Worktree 查询都携带所选 Workspace id。Host 解析权威的规范化 Workspace 路径，并拒绝缺失、已删除或越界的路径。浏览器不能提供任意文件系统根目录或命令行。请求支持取消，并受条目数、字节数、匹配数和耗时上限约束，因此展开大型仓库或替换搜索时不会保留失效工作。

- 资源管理器按需加载目录子项，目录排在文件之前，按 Workspace 保存展开状态，为每个目录呈现加载和重试状态，且不跟随解析后越出 Workspace 根目录的路径。
- 搜索接受纯文本和可选 include pattern，流式或分页返回有界匹配，明确报告截断，在新查询替换旧查询时取消旧查询，并通过现有文件位置展示路径打开结果。
- 源代码管理发现包含 Workspace 路径的仓库，解析稳定的机器可读 Git 状态格式，把已暂存、未暂存、未跟踪、冲突和重命名路径分组；`0.3.0` 中保持只读。非仓库 Workspace 显示明确的空状态，而不是失败的命令卡片。

Host 适配器使用现有文件系统与子进程能力。它负责固定 Git argv、环境、输出上限、取消、规范根路径检查，以及到已验证 RPC 值的投影。UI 组件只消费这些投影，不直接调用 shell 工具或桌面桥接。

## 消息复制

`MessageIconActions` 继续作为唯一的剪贴板实现。此项工作审计所有普通用户消息和助手消息渲染器，把完整的用户可见纯文本传给该组件，并把复制控件放在消息状态栏旁。操作在键盘聚焦和消息悬停时可见，具有持久的无障碍名称，使用现有的临时勾选图标报告成功，并与分支和反馈操作共存。工具卡片、推理行、上下文注入和仅状态行继续使用各自的复制行为；不表示一条普通消息时则保持排除。

## API、余额与运行时负载

标题栏在余额控件前增加状态区。API 状态有四个明确值：检查中、已连接、不可用和未配置。桥接从余额使用的同一条凭据安全请求路径派生状态，不返回任何凭据材料，区分凭据缺失与传输或提供方失败，并在标记当前连接失败时保留最后一次成功余额。点击余额控件会启动一次去重刷新，向辅助技术暴露忙碌状态，且不会形成重叠轮询。

标题栏还显示一个带本地化无障碍标签的负载 emoji。该指示器描述本地应用工作负载，而非物理能耗。原生宿主以固定低频率采样桌面进程及其管理的运行时进程树，投影成小型归一化等级，并且不暴露进程清单。阈值迟滞与最短停留时间避免 emoji 快速变化。测量未知或平台不支持时显示中性状态；遥测失败不会影响启动或 agent 执行。

初始等级为平静、活跃、繁忙和饱和。具体 CPU 与内存阈值是桌面壳子拥有的配置值，测试固定等级转换、迟滞、不支持的宿主和资源释放。UI 把等级映射成稳定 emoji 与文本，不尝试估算瓦数、成本或环境影响。

## 图标与启动界面

一份黑色透明背景源资产成为桌面图标系列的所有者。构建过程重新生成或验证 Tauri、安装程序、托盘和窗口消费的 PNG 与 ICO 尺寸。启动界面使用图像元素渲染同一资产，替代渐变色块，并使用浅色中性承托形状在深色启动主题中保持对比度。资产验证会拒绝缺失尺寸，以及启动界面引用与打包图标源不一致的情况。

## 交付计划

1. **版本基础：**把所有桌面版本来源提升到 `0.3.0`，Changelog 章节保持未发布，定义工作台 slot 与有界 Host 响应类型，并为新插件增加组装测试组合。
2. **低风险交互完善：**补齐普通消息复制覆盖，替换图标系列与启动界面渲染。记录键盘、屏幕阅读器名称、悬停、打包图标和启动界面证据。
3. **运行状态区：**增加共享的 API/余额刷新状态机、原生负载采样、标题栏渲染、超时与资源释放行为，并为每种状态转换增加确定性测试。
4. **Worktree 读取功能：**在同一套规范根路径与取消基础设施上，依次交付资源管理器、搜索和只读源代码管理。每个视图都带独立的聚焦 Host、客户端和组装浏览器测试。
5. **发布加固：**运行 Windows 打包安装与升级冒烟测试，确认单实例与托盘行为不受影响，从真实组装应用录制必需的 GUI GIF，使用已交付行为更新双语 README 与 Changelog，并仅在全部验收条件通过后推送 `v0.3.0` Release 标签，使标签门控工作流从已验收提交创建草稿。

## 备选方案

**把五项改动都放进注入的桌面桥接。** 这种方式可以更快做出原生构建原型，但会绕过客户端 slot 架构、重复文件系统与子进程策略，并使浏览器组合测试无法覆盖 Worktree UI。桥接继续只负责原生状态栏和凭据安全的桌面集成。

**向浏览器暴露不受限的 shell 或文件系统端点。** 通用端点会减少 Host 方法数量，但也会让远程页面输入选择根目录和命令。采用固定操作与规范化 Workspace 解析可限制权限并让上限可测试。

**把 Worktree 模式作为 Git checkout 管理。** 创建和切换 Git worktree 是破坏性工程变更，需要分支、脏状态、冲突和清理策略。`0.3.0` 提供只读工程 Worktree 视图；checkout 管理需要独立提案。

**估算物理能耗。** CPU 利用率无法在不同硬件和操作系统上可靠推导设备功耗。因此 emoji 报告应用工作负载，并据此标注。

**为新按钮创建第二套剪贴板实现。** 共享消息状态栏已经处理剪贴板回退、待完成写入、成功计时和资源释放。扩展其渲染器覆盖可以避免行为分叉。

## 验收条件

- 桌面包、Rust crate、Tauri 配置、lockfile、标题栏版本徽标、安装程序元数据和草稿 Release 的版本均为 `0.3.0`。
- sidebar 切换控件支持键盘操作，且切换模式时保留 Workspace/Session 选择；资源管理器、搜索和源代码管理始终限定在所选 Workspace 内，并正确处理取消、重连、空状态、错误和大型结果状态。
- 每条普通用户消息和助手消息都提供一个相邻复制操作，复制完整可见纯文本，并给出无障碍成功反馈。
- API 状态区分检查中、已连接、不可用和未配置；手动余额刷新会去重，失败时保留最后一次成功金额，并且绝不暴露凭据。
- 负载 emoji 只按所记录等级和迟滞变化，带无障碍文本状态，并在无法采样时退化为中性状态。
- 启动界面、窗口、托盘、安装程序和打包图标资产派生自同一份黑色源图，并在支持的背景上保持清晰。
- 聚焦单元测试、Host 集成测试、组装的无密钥浏览器场景、Windows 打包冒烟测试及用户可见 GIF 证据覆盖受影响行为。发布草稿 Release 前，文档、lint、构建、hygiene 与相关体积检查全部通过。

## 风险

大型目录枚举和仓库状态读取可能恰好在应用已经繁忙时消耗资源；严格上限、取消、懒加载和采样间隔是发布要求，而不是后续优化。Git 状态在重命名、子模块、忽略文件、嵌套仓库和非 UTF-8 路径方面存在差异，因此 `0.3.0` 保持只读，并且必须展示而非猜测不支持的条目。标题栏同时容纳余额、API 状态、工作负载、版本和窗口控件，在窄窗口中可能拥挤；响应式优先级和无障碍标签必须保留窗口拖动与控制功能。黑色图形会在深色表面上消失，因此周围 UI 不提供对比度时，规范资产需要承托处理。
