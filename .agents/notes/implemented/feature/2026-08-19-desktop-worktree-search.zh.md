# Agent Note: 桌面端 Worktree Search

Status: implemented

[English](2026-08-19-desktop-worktree-search.md) | 中文

## 问题

桌面 Worktree 需要工程文本搜索，但不能允许浏览器输入选择任意文件系统根目录、命令或无界结果集。

## 决策

桌面 bridge 暴露 `GET /dsh-bridge/worktree/search`，请求包含已注册的 `workspaceId`、非空纯文本 `query`、供 Host 调用方使用的可选正向 `include` glob、严格的区分大小写和全字匹配开关，以及不透明分页游标。Host 从 `ctx.workspaceRegistry` 与 `ctx.fs` 解析规范化 Workspace 根目录，再通过 `ctx.subprocess` 使用固定参数运行 ripgrep 内容扫描和文件列表扫描；进程工作目录固定为 Workspace 根目录，遵循 ignore 规则、默认跳过隐藏项、固定排除 VCS 与生成目录且不经过 shell。浏览器不能提供根目录或命令。

Search 增量解析 `rg --json` 输出，并以 NDJSON 流提供相对文件路径、行号和有界预览。ripgrep 运行时持续发送内容匹配事件；终止事件在补充文件路径匹配并应用可配置的匹配数、响应字节、原始输出、文件大小、进程退出宽限期和耗时上限后，提供权威分页结果。游标记录最后返回的路径与行号；统一的代码单元路径顺序和数字行号顺序既用于结果排序，也用于在确定性重扫时丢弃游标之前的匹配。替换查询会取消之前的 HTTP 请求；超时、输出截断、无效输入、缺失 Workspace 和进程失败都返回明确的机器可读事件或响应。未请求流式传输时，该路由仍保留 JSON 响应。

Worktree client 渲染一个文件列表，并将搜索工具栏放在列表上方。工具栏只有一个可填充的文本输入框，部分输入经过短暂防抖后触发搜索，按 Enter 可立即提交，通过输入框悬浮提示提供使用说明，右侧提供区分大小写和全字匹配按钮。客户端以短暂进入过渡动画追加流式匹配，操作系统请求减少动态效果时禁用动画，再使用终止分页结果校正列表。结果可以表示内容行或匹配的相对文件路径。清空输入会恢复默认文件列表。Search 呈现空结果、加载、错误、部分结果和分页状态；选择结果后通过现有 `workspaces.openPath()` Host 打开通路，将结果相对路径拼接到所选 Workspace 根目录。Git 状态与资源管理器条目一起显示，不再作为独立的 Worktree 窗口。

## 备选方案

**暴露通用 shell 或文件系统搜索端点**：否决。固定 ripgrep 参数和由注册表拥有的根目录使浏览器输入远离命令和路径权限。

**向文件系统 Service Definition 增加递归搜索方法**：否决。现有子进程能力和打包 ripgrep 已提供有界进程执行，而通用提供方方法会把搜索语义强加给远程文件系统实现。

**一次响应返回完整匹配列表**：否决。分页游标和响应上限限制浏览器负载，并使截断可见。

## 后果

后续分页会从规范化根目录重新扫描 Workspace，因此会增加 I/O，但换取不透明的无状态游标。ripgrep 默认遵循仓库 ignore 规则并跳过隐藏项，同时通过固定模式排除常见 VCS 与生成目录，避免把延迟消耗在依赖和构建产物上。Host 流式发送解析后的匹配，而不是原始 ripgrep 字节；达到原始输出上限时会终止扫描，保留已解析的完整匹配记录，并把终止结果列表标记为不完整。Search 只读；Git 状态使用独立的固定 Host 路由，并以资源管理器装饰显示。如果大型源码树仍达不到延迟目标，下一步应增加持久化增量索引。

## 测试

桌面测试固定纯文本、include 与匹配开关校验、游标拒绝、结果与游标使用同一顺序、只以根目录为目标的固定参数、性能排除项、跨 UTF-8 数据块边界的增量 JSON 解析、原始输出终止、伴随进程启动失败清理和匹配投影。独立 bridge TypeScript 构建会编译 Search Host 路由与 Worktree client；Explorer、Search 和虚拟列表聚焦测试集通过。
