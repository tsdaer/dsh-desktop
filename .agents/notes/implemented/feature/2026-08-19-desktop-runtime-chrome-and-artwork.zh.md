# Agent Note: 桌面端运行状态栏与图形

Status: implemented

[English](2026-08-19-desktop-runtime-chrome-and-artwork.md) | 中文

## 问题

桌面标题栏只显示余额，没有明确的 API 连接状态或直接刷新操作。启动界面与打包图标文件也没有共享本地验证源，原生壳没有用于显示应用及其管理运行时负载的有界指标。

## 决策

桥接余额响应现在在无凭据安全余额投影旁携带 `connected`、`unavailable` 或 `unconfigured` 之一。标题栏从 `checking` 开始，显示四种明确 API 状态；刷新失败时保留最后一次成功余额。余额控件支持键盘操作，在请求期间暴露 `aria-busy`，点击和窗口重新可见时刷新，并对并发请求去重。

Rust 壳拥有持久的 `sysinfo` 采样器。它测量桌面进程及其管理的运行时进程树，合并归一化的进程 CPU 与内存负载，并且只返回 `unknown`、`calm`、`active`、`busy` 或 `saturated`。第一次采样显示中性状态；非对称转换阈值与四秒最短停留时间避免等级快速变化。进程缺失、不支持的测量和采样失败都返回 `unknown`，不会影响启动或 agent 执行。

远程主窗口 capability 明确授予 `allow-runtime-status`；其他窗口通过不声明该权限保持不可用。这样，被拒绝的状态调用不会被误认为有效的负载采样。

规范图形源是 `apps/desktop/src/icon.svg`，它是一份由启动界面使用的透明黑色 fish 图形。`gen-icons.mjs` 把它栅格化为 16、32、48、256 和 512 像素 PNG，并生成多尺寸 ICO。启动界面把 SVG 放在浅色中性承托形状上，使黑色图形在深色主题中保持可见。

## 测试

Rust 单元测试固定等级阈值、非对称迟滞和最短停留时间。桥接/client 构建、图标生成和聚焦桌面 Vitest 覆盖通过。`cargo check` 已解析并编译 `sysinfo`，但 Tauri build script 在写入生成权限目录时被 Windows 权限错误阻断；使用仓库内全新的 target 目录时，同一份源码可以编译且 Rust 测试通过。

## 备选方案

**向浏览器暴露原始进程指标。** 不采用，因为标题栏需要小型负载标签，而不是进程清单或宿主遥测。原生命令只返回归一化等级。

**新增独立的 API 健康请求。** 不采用，因为这会重复凭据解析并形成第二条提供方失败路径。现有余额代理是状态和余额共同使用的单一凭据安全请求。

**继续以 upstream 的彩色 FishLogo 作为图标源。** 不采用，因为启动界面、安装器、托盘和窗口需要一份桌面拥有的黑色源资产与确定性验证。源资产现在位于桌面 frontend 下，生成文件都由它派生。

## 后果

标题栏增加了紧凑状态区，在窄窗口中必须保留标签和控件。负载采样新增 `sysinfo` 依赖和低频原生进程刷新，但中性回退使遥测不影响核心功能。重新生成图标需要 `sharp`；当所需栅格器不可用时，生成器显式失败，不再静默生成占位图。
